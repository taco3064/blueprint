'@kekkai/blueprint': patch
---

Repairs the defects the 4.1 live field round measured against real adoptions.

**Emitted output.** An `additionalAliases` target above `sourceRoot` made the module-root ban appear twice in `no-restricted-imports.paths`, which declares `uniqueItems`, so ESLint rejected the whole config and no rule ran at all. The `deep-import` finding offered only "import it through its entry", which a stylesheet has no way to follow, and now also names co-location.

**Evidence and verification.** `inspect` now honours `architecture.layerFiles` when deciding a folder is undeclared, so it and `emit/lint` stop giving opposite answers about the same folders. In a monorepo, an ancestor ESLint config counts as wired when `basePath` is set to a `new URL()` naming the application — proven rather than matched against the generated sample's identifier and its leading `./`, which had left correctly wired repositories reported unwired while `init` regenerated a reference file that `doctor` then flagged. The install note now says its carrier peer-range claim covers the carriers it installs and not Blueprint's own parser dependencies, whose unmet peers an adopter otherwise sees unexplained.

**Adoption guidance.** The authoring method asks what each layer is responsible for before ordering them, and states that the import matrix is evidence for that decision rather than its author. Module-first says it is closed-world at the source root, and `inspect` now measures it: a module-first project whose governed source imports a directory beside `sourceRoot` that holds source of its own is reported as an error naming those directories, because the application's architecture already extends past the configured scan boundary and no rule, cycle check, or coverage number observes what lies outside it. A directory nothing governed imports is not reported, so tooling and docs folders beside a source root stay quiet. Both transformation playbooks warn that project configuration naming the old paths does not fail when it stops matching — a coverage `include` that matches nothing passes its threshold. The doctor acceptance condition asks for no `✗` and a named reason behind every `⊘`, instead of requiring every skip to disappear, which several correct project shapes cannot do. `init` warns when an installed formatter and the documents Blueprint regenerates will take turns rewriting each other.

**Lifecycle.** `remove` states what the wiring it asks you to delete is emitting today, and how much of it cannot be rebuilt without the package, at the point that decision is made. A layer-first → module-first transformation records the source layer declarations in its Git-backed origin, and the reverse leg restores the recorded container identity and layer policy instead of falling back to `containers/<module>` — except where a split or an explicit merge superseded that identity, and for repositories with no layer-first origin at all.
